원본 문서
   ↓
1. 청킹 (텍스트 자르기)
   ↓
   "1.20 패치에서 추가된 새 블록..." 같은 청크들
   ↓
2. 메타데이터 부착 ← 여기!
   ↓
   {
     "text": "1.20 패치에서 추가된 새 블록...",
     "metadata": {"version": "1.20", "source": "wiki"}
   }
   ↓
3. 임베딩 생성 (text 부분만 벡터화, 메타데이터는 벡터화 안 됨)
   ↓
4. Vector DB 저장 (text + embedding + metadata 함께)

```
1. 메타데이터는 임베딩되지 않습니다 (벡터로 변환 안 됨)
   → 텍스트 본문(page_content)만 벡터로 변환됨
   → 메타데이터는 별도 컬럼으로 저장 (관계형 DB의 인덱스 칼럼처럼)

2. 메타데이터는 청크 단위로 붙습니다
   → 청크마다 다른 메타데이터를 가질 수 있음
   → 같은 문서에서 나온 청크는 보통 같은 메타데이터 공유

3. 메타데이터는 청킹 직후에 붙이는 게 일반적
   → 청크 만들면서 "이 청크가 어디서 왔는지"를 함께 기록
   → Cross-encoder는 검색 시점이라 메타데이터 부착과 무관
```
