```
1. 메타데이터는 임베딩되지 않습니다 (벡터로 변환 안 됨)
   → 텍스트 본문(page_content)만 벡터로 변환됨
   → 메타데이터는 별도 컬럼으로 저장 (관계형 DB의 인덱스 칼럼처럼)

2. 메타데이터는 청크 단위로 붙습니다
   → 청크마다 다른 메타데이터를 가질 수 있음
   → 같은 문서에서 나온 청크는 보통 같은 메타데이터 공유

3. 메타데이터는 청킹 직후에 붙이는 게 일반적
   → 청크 만들면서 "이 청크가 어디서 왔는지"를 함께 기록
   → Cross-encoder는 검색 시점이라 메타데이터 부착과 무관
```

오늘 한 줄 요약:

메타데이터는 청크에 붙이는 구조화된 라벨이고, 검색 전에 사전 필터로 사용하면 정확도와 속도 둘 다 올라간다. 자동화는 데이터 수집 단계에서 코드로 부착하는 게 일반적이고, 누락은 기본값("unknown")으로 처리하면 일관성이 유지된다.

배운 것:

메타데이터의 4가지 조건 (카테고리형, 검색용, 정형, 가벼움)
ChromaDB의 메타데이터 제약 (단순 타입만)
where 필터 연산자 ($and, $or, $in, $gte 등)
자동화 방법 4가지 (수집 단계, 정규식, LLM, 파일 시스템)
누락 처리 패턴 ("unknown" + $ne 필터)
