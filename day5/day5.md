1) Part 1 — Bi-encoder vs Cross-encoder
```
[Bi-encoder]
  질문 → [모델] → 벡터 ─┐
                        ├→ 코사인 유사도 → 점수
  문서 → [모델] → 벡터 ─┘
  
  → 질문과 문서가 따로 처리됨

[Cross-encoder]
  질문 + 문서 → [모델] → 점수
  
  → 질문과 문서가 함께 처리됨
  → 모델이 "둘의 관계"를 직접 본다
```
> Bi-encoder:
  인덱싱 시점에 문서 100만 개 임베딩 → 한 번만
  검색 시점에는 질문 임베딩 1번만
  → 검색 1회당: 모델 호출 1번 + 거리 계산 100만 번 (빠름)
Cross-encoder:
  미리 계산 못 함! 질문이 들어와야 시작 가능
  검색 시점에 (질문, 문서1), (질문, 문서2), ... 100만 번 모델 호출
  → 검색 1회당: 모델 호출 100만 번 (사용 불가)

---
2) 사용하는 방법

[2단계 검색 파이프라인]
1단계 (빠르게 후보 좁히기):
  Bi-encoder + HNSW + (BM25 + RRF)
  → 100만 개 → 30개 후보로 압축
  → 수십 ms

2단계 (정확하게 재정렬):
  Cross-encoder
  → 30개를 다시 정밀 채점
  → 30번만 모델 호출하면 되니까 빠름 (수백 ms)
  → 최종 5개 선택

3) Re-Ranking 파이프라인
```
[질문]
   ↓
Stage 1: 후보 검색 (빠름)
   ├─ Dense (Bi-encoder + HNSW)
   ├─ BM25
   └─ RRF로 결합
   ↓
   상위 N개 후보 (예: 30개)
   ↓
Stage 2: 재정렬 (정확함)
   └─ Cross-encoder가 각 후보의 점수 재계산
   ↓
   상위 K개 (예: 5개)
   ↓
LLM에 전달 → 답변 생성

-----------------------------
[전체 파이프라인]

Dense ────┐
           ├─→ RRF ─→ 30개 후보 ─→ Cross-encoder ─→ 5개 ─→ LLM
BM25 ────┘
   ↑                      ↑
   Hybrid                 Re-ranking
   (Day 4)                (Day 5)
   후보 풀 개선            순위 정밀화
```
---
4) N과 K의 관계 — 일반적인 비율

```
N=30, K=5라면:
  Cross-encoder는 30개를 보고 그 중 5개 선택
  → 6개 중 1개를 "최고"로 뽑는 셈
  → 충분한 후보 풀에서 정밀하게 고르는 효과

N=10, K=5라면:
  10개 중 5개 선택 (절반 통과)
  → Re-ranking 효과가 약함
  → 어차피 Bi-encoder 1단계 결과의 절반은 통과하므로 큰 차이 없음
```
