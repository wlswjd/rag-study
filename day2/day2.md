검색에서 99위 vs 100위 구분이 의미가 없습니다. 사용자는 어차피 상위 5~10개만 봅니다.
99% 정확도로 1000배 빠른 게 100% 정확도로 느린 것보다 낫습니다.

- HNSW (Hierarchical Navigable Small World) : 그래프 구조로 빠르게 가까운 점을 찾는다 / ChromaDB, Pinecone, Qdrant 등 대부분의 Vector DB

Small World : 
대부분의 친구는 가까운 동네 사람(local connection)
하지만 가끔 멀리 사는 친구도 있다(long-range connection)

[부산 사람 A]
  ├── 부산 친구들 (가까운 연결)
  └── 서울 사는 친구 1명 (먼 연결)
              │
              ├── 서울 친구들
              └── 미국 사는 친구 1명 (더 먼 연결)
                          │
                          └── 미국 친구들 ...

"Navigable" — 탐색이 가능하다
시작점: [자동차 엔진오일]  (질문과 거리 멀음)
   ↓ 이웃 확인
   → [자동차 부품 추천]    (여전히 멀음)
   → [반려동물 용품]       (가까워짐!) ← 이리로
   ↓
[반려동물 용품]
   ↓ 이웃 확인
   → [고양이 모래]         (조금 멀어짐)
   → [강아지 산책 용품]    (가까움) ← 이리로
   ↓
[강아지 산책 용품]
   ↓ 이웃 확인
   → [강아지 간식 추천]    (매우 가까움) ← 이리로
   ↓
[강아지 간식 추천]
   ↓ 이웃 확인
   → [강아지 사료 종류]    (가장 가까움!) ← 정답

----
"Hierarchical" — 계층 구조
Layer 2 (최상층, 매우 sparse)
  ●─────────────●─────────────●
  먼 거리 점프만 가능

Layer 1 (중간, 적당히 sparse)
  ●───●─────●───●─────●───●
  중간 거리 점프

Layer 0 (최하층, 모든 노드 포함, dense)
  ●─●─●─●─●─●─●─●─●─●─●─●─●─●─●
  세밀한 검색

[검색 흐름]

1. 최상층(Layer 2)에서 시작
   → 노드가 적으니 빠르게 대략 가까운 영역으로 이동

2. Layer 1로 내려가서 그 영역 안에서 더 정밀하게 탐색
   → 중간 단위로 좁히기

3. Layer 0으로 내려가서 최종 정밀 검색
   → 정확한 가장 가까운 K개 찾기

데이터가 20개밖에 안 되어서 차이가 미미할 수 있습니다. 하지만 다음 두 가지를 확인할 수 있습니다.
1. ef가 작을 때 (5)
   → 매우 빠름
   → 결과 순위가 ef=100과 약간 다를 수 있음

2. ef가 클 때 (100)
   → 살짝 느림
   → 더 정확한 결과 (Brute Force에 가까워짐)
실무 감각: 데이터가 100만 개쯤 되면 ef=10과 ef=200의 검색 시간 차이가 10배 이상 나면서, 정확도는 95% vs 99% 정도 됩니다. 어떤 게 맞다는 답은 없고, 서비스 요구사항에 맞게 조정합니다.
